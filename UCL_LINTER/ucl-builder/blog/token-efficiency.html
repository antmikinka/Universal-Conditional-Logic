Specification, overhead, and the 29.8% cut

Universal Conditional Logic treats a prompt as something you can structure and overdo. The preprint is arXiv:2601.00880.

What was measured

The repository’s design is 13 models, 7 conditions, and 4 iterations: 364 invocations. The conditions run from no system prompt, through a long baseline, to UCL versions v1 through v4.1. The analysis CSV is marked N=305. The builder’s About box cites that 305.

The reported result is a 29.8% token reduction, with quality held. Past a specification level of about S* = 0.509, more specification degraded quality. Version v2 is the over-specified case in the README. That curve is about prompts, not about tool JSON.

What the formula is for

Structural overhead is written Os = γ Σ ln(Ck). It prices the pieces you add: conditions, switches, procedure length. Keyword conditions were the cheaper shape. A switch-heavy prompt paid more.

Do not add this 29.8% to the later tool-catalog token gap. One number is a specification study. The other is a name list versus a pasted schema. The tool note is separate.
